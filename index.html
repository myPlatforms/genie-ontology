SUMMARY

한눈에 보기

무엇인가

Genie One·Genie Code와 외부 AI 에이전트가 함께 쓰는 비즈니스 컨텍스트 지도입니다. 2026-11-09에 GA(General Availability, 정식 출시)됐고 기본으로 켜져 있습니다.

어떻게 만들어지나

기존 자산과 사용 이력에서 자동으로 학습한 지식에, 사람이 직접 정의하고 인증한 지식을 더합니다. 둘이 충돌하면 사람이 정의한 쪽이 우선합니다.

무엇부터 할까

핵심 KPI(Key Performance Indicator, 핵심 성과 지표)를 메트릭 뷰로 정의하고, 믿을 자산은 인증, 오래된 자산은 폐기 표시를 합니다. 나머지는 Genie가 학습합니다.

01

왜 에이전트에게 온톨로지가 필요한가

AI 에이전트가 데이터 플랫폼에서 보는 것은 테이블과 컬럼 이름뿐입니다. 그런데 사람의 질문에는 회사마다 정의가 다른 비즈니스 용어가 섞여 있습니다.

질문: "3분기 활성 고객당 매출은 얼마인가요?"

에이전트가 보는 것

fct_revenue_dailynet_rev, gross_rev, recog_rev
customer_factsis_active, active_flag, status
revenue_snapshot_q3rev_q3, rev_q3_final, rev_q3_adj

에이전트에게 필요한 것

매출의 정의순매출인가, 총매출인가, 인식 매출인가?
활성 고객의 기준이번 달 로그인? 결제? 둘 다?
믿을 원천비슷한 매출 테이블 중 어느 것이 공식인가?

이 빈칸을 에이전트가 매번 추측하면 세 가지 비용이 생깁니다.

  • 틀린 답: 정의를 잘못 고르면 숫자가 그럴듯하게 틀립니다.
  • 많은 토큰: 맞는 테이블과 정의를 찾느라 탐색을 반복합니다.
  • 느린 응답: 질문할 때마다 컨텍스트를 처음부터 다시 추론합니다.

정의를 BI 도구마다 따로 두거나, 별도의 지식 그래프를 사람이 손으로 관리하는 방식은 데이터와 정의가 떨어져 있어 유지하기 어렵습니다. Genie Ontology는 정의를 데이터 플랫폼(Unity Catalog) 위에 두고, 나머지는 자동으로 학습하는 방식으로 이 문제를 풉니다.

02

Genie Ontology란

공식 문서는 Genie Ontology를 "AI 에이전트에게 조직의 비즈니스를 이해하는 지도를 주는 통합 컨텍스트 레이어"라고 정의합니다. 핵심은 세 가지입니다.

  • 하나의 온톨로지를 여러 곳에서 씁니다. Genie One과 Genie Code가 같은 온톨로지를 검색하므로, 한 번 정리한 컨텍스트가 두 곳에 모두 적용됩니다.
  • 외부 에이전트도 씁니다. 다른 플랫폼의 에이전트는 Genie One MCP(Model Context Protocol) 서버로 접근하고, 이때도 같은 Unity Catalog(UC) 권한이 적용됩니다.
  • 권한을 지킵니다. 사용자는 자신이 접근할 수 있는 자산에서 나온 지식만 봅니다.
여기서 말하는 '온톨로지'

OWL처럼 형식 언어로 개념을 하나하나 모델링하는 전통적인 온톨로지와는 다릅니다. 이미 있는 자산(메트릭 뷰·대시보드·쿼리 등)에서 자동으로 학습한 지식과, UC semantics로 사람이 정의한 지식을 합친 컨텍스트 레이어입니다. 처음부터 전부 모델링하지 않아도 바로 쓸 수 있습니다.

03

두 종류의 지식: 학습된 지식과 모델링된 지식

공식 문서의 표현을 빌리면 "중요한 것은 모델링하고, 나머지는 Genie가 학습하게" 하는 구조입니다.

구분학습된 지식 (Learned knowledge)모델링된 지식 (Modeled knowledge)
만드는 주체Genie가 자동으로 추출·유지사람이 정의·관리·인증
원천메트릭 뷰, 대시보드, SQL 쿼리(dbt 같은 외부 도구가 실행한 쿼리 포함), Genie Agents, 외부 지식 소스(Power BI, Beta)UC semantics: 메트릭 뷰, 도메인(Domains), Pages, 인증·폐기. 큐레이션한 Genie Agents도 권위 있는 원천으로 취급
저장 형태스니펫(snippet): 지표 정의, 권위 있는 원천, 비즈니스 규칙UC 객체와 태그, Pages 문서
권위출처·사용 빈도·최신성으로 권위 점수를 매김학습된 지식보다 우선
수정 방법직접 편집 불가 → 원천 자산을 고치거나 모델링된 지식으로 정의UC·Discover에서 직접 수정
권한UC 권한으로 제한. 단 외부 지식 소스 스니펫은 계정 전체 사용자에게 보임UC 권한 / 도메인 권한을 따름

스니펫은 이런 모습입니다

지표 정의

"'활성 사용자'는 모든 플랫폼에서 중복을 제거한 고유 사용자다."

권위 있는 원천

"매출 질문은 큐레이션된 Finance Genie Agent로 답한다."

비즈니스 규칙

"'적격 리드'는 데모가 예약된 뒤에만 센다."

출처: 공식 문서 Genie Ontology의 예시를 옮김. Genie One 응답 아래 Genie Ontology를 누르면 사용된 스니펫의 설명·원천 자산·작성자·도메인·리니지를 볼 수 있습니다.

충돌하면 누가 이기나

Genie는 인증 여부, 인기도, 작성자 같은 신호로 원천의 권위를 판단합니다. 같은 주제라면 일반적으로 모델링된 지식 · 인증된 자산 · 큐레이션된 Genie Agents가 학습된 지식보다 우선합니다. 그래도 판단할 수 없으면 사용자에게 되묻습니다.

04

동작 방식

원천에서 지식을 모아 두고, 질문이 들어오면 권한을 적용해 관련 있는 지식만 골라 에이전트의 추론에 넣습니다.

순위는 공식 블로그에서 "PageRank와 비슷한 방식"으로 소개됐습니다. 정의가 어디서 왔는지, 작성자의 상대적 권위, 얼마나 자주 쓰이는지, 인증되고 널리 쓰이는 자산과 얼마나 가까운지, 얼마나 최신인지를 따져 가중치를 줍니다.

예시 ① 핵심 KPI를 메트릭 뷰로

정의를 한 곳에 두면 대시보드·Genie·SQL이 같은 숫자를 씁니다. 아래는 "매출 = 배송 완료 주문만"이라는 규칙을 메트릭 뷰에 넣은 예입니다. samples.tpch를 쓰므로 어느 워크스페이스에서나 실행할 수 있고, 실제 워크스페이스에서 실행해 확인했습니다.

SQL · YAML
CREATE OR REPLACE VIEW <catalog>.genie_ontology_lab.orders_metrics
WITH METRICS
LANGUAGE YAML
AS $$
version: 1.1
comment: 주문·매출 핵심 지표. 매출은 배송 완료(F) 주문만 집계한다.
source: samples.tpch.orders
joins:
  - name: customer
    source: samples.tpch.customer
    on: source.o_custkey = customer.c_custkey
fields:
  - name: order_month
    expr: DATE_TRUNC('MONTH', o_orderdate)
    display_name: 주문 월
    synonyms: ['월', 'order month']
  - name: market_segment
    expr: customer.c_mktsegment
    display_name: 시장 세그먼트
    synonyms: ['세그먼트', '고객군']
  - name: order_status
    expr: CASE o_orderstatus WHEN 'F' THEN '배송 완료' WHEN 'O' THEN '진행 중' ELSE '부분 배송' END
    display_name: 주문 상태
measures:
  - name: order_count
    expr: COUNT(1)
    display_name: 주문 수
  - name: recognized_revenue
    expr: SUM(o_totalprice) FILTER (WHERE o_orderstatus = 'F')
    display_name: 확정 매출
    comment: 배송 완료(F) 주문의 금액 합계. 진행 중·부분 배송 주문은 제외한다.
    synonyms: ['매출', '확정 매출', 'revenue']
    format:
      type: currency
      currency_code: USD
  - name: revenue_per_customer
    expr: MEASURE(recognized_revenue) / COUNT(DISTINCT o_custkey)
    display_name: 고객당 확정 매출
$$;
SQL
-- Measures must be wrapped in MEASURE(); SELECT * is not allowed
SELECT market_segment,
       MEASURE(order_count)          AS orders,
       MEASURE(recognized_revenue)   AS revenue,
       MEASURE(revenue_per_customer) AS revenue_per_customer
FROM <catalog>.genie_ontology_lab.orders_metrics
WHERE order_month BETWEEN DATE'1995-01-01' AND DATE'1995-12-01'
GROUP BY ALL
ORDER BY revenue DESC;
요건과 문법 메모
  • 메트릭 뷰를 만들려면 원천에 SELECT, 대상 스키마에 CREATE TABLE·USE SCHEMA, 카탈로그에 USE CATALOG 권한이 필요합니다. 컴퓨트는 DBR(Databricks Runtime) 17.3 이상 또는 SQL 웨어하우스를 씁니다.
  • display_name·synonyms·format은 YAML 사양 1.1부터 쓸 수 있습니다. 동의어는 항목마다 최대 10개입니다.
  • fields가 현재 권장 키이고, 예전 dimensions도 계속 받아들입니다.

예시 ② 인증과 폐기

인증은 시스템 태그 system.certification_status 하나로 표시합니다. 테이블·뷰·메트릭 뷰·볼륨·함수·모델·대시보드·Genie Agents·Apps·노트북·Pages에 붙일 수 있습니다.

SQL
-- Mark the governed metric view as the trusted source
SET TAG ON TABLE <catalog>.genie_ontology_lab.orders_metrics
  `system.certification_status` = `certified`;

-- Mark the legacy view as outdated and point to its replacement
SET TAG ON TABLE <catalog>.genie_ontology_lab.orders_revenue_old
  `system.certification_status` = `deprecated`;
COMMENT ON TABLE <catalog>.genie_ontology_lab.orders_revenue_old
  IS '구 매출 뷰(모든 상태 합산). orders_metrics를 사용할 것';

-- Check the tags
SELECT table_name, tag_name, tag_value
FROM <catalog>.information_schema.table_tags
WHERE schema_name = 'genie_ontology_lab';

필요 권한: system.certification_status 태그의 ASSIGN 권한, 그리고 객체 소유자이거나 APPLY TAG·USE SCHEMA·USE CATALOG 권한. UI에서는 객체의 ⋮ 메뉴 → Assign certification으로 합니다.

예시 ③ 외부 에이전트에서 같은 온톨로지 쓰기

Genie One MCP 서버에 연결하면 외부 에이전트도 같은 정의와 권한으로 답을 받습니다. 먼저 권한을 줍니다.

BASH
# Grant EXECUTE on the Genie One MCP service (securable type: mcp_service)
databricks grants update mcp_service system.ai.genie_one_mcp \
  --json '{"changes": [{"principal": "someone@example.com", "add": ["EXECUTE"]}]}'

# Check effective permissions
databricks grants get-effective mcp_service system.ai.genie_one_mcp --principal someone@example.com

호출자에게는 이 밖에 system 카탈로그의 USE CATALOG, system.ai 스키마의 USE SCHEMA, 그리고 워크스페이스 할당이 필요합니다. MCP 클라이언트에 넣을 서버 주소는 다음과 같습니다.

URL
https://<workspace-hostname>/ai-gateway/mcp-services/system.ai.genie_one_mcp?o=<workspace-id>

Python에서는 MCP SDK와 Databricks SDK로 질문하고, 답이 나올 때까지 폴링합니다. 공식 문서 예시를 줄인 코드입니다.

PYTHON
# pip install mcp databricks-sdk
import asyncio
from databricks.sdk import WorkspaceClient
from mcp.client.session import ClientSession
from mcp.client.streamable_http import streamablehttp_client

w = WorkspaceClient()
url = f"{w.config.host}/ai-gateway/mcp-services/system.ai.genie_one_mcp?o={w.get_workspace_id()}"

async def ask(session, question):
    state = (await session.call_tool("genie_ask", {"question": question})).structuredContent
    # Poll until Genie finishes (completed, incomplete, or failed)
    while state["status"] == "in_progress":
        poll = await session.call_tool("genie_poll_response", {
            "conversation_id": state["conversation_id"],
            "response_id": state["response_id"],
        })
        state = poll.structuredContent
    return state

async def main():
    async with streamablehttp_client(url, headers=w.config.authenticate()) as (read, write, _):
        async with ClientSession(read, write) as session:
            await session.initialize()
            answer = await ask(session, "1995년 시장 세그먼트별 확정 매출을 알려줘")
            print(answer["status"], answer.get("final_answer"))

asyncio.run(main())
사용자 대신 호출하기

공식 문서는 사용자 대신 호출(on-behalf-of user OAuth, ai-gateway 스코프)을 권장합니다. 그래야 답변이 그 사용자의 UC 권한 범위로 제한됩니다. 자동화 작업에는 서비스 주체 인증도 쓸 수 있습니다. 답변은 비동기라 폴링이 필요하고, 결과 표는 컨텍스트 보호를 위해 잘릴 수 있습니다(전체 결과는 genie_get_query_result).

06

30분 실습: 인증한 지표를 Genie가 고르는지 확인하기

예시 ①·②를 이어서 실행해 봅니다. 같은 '매출'을 계산하는 뷰 두 개(새 메트릭 뷰, 구 뷰)를 만들고 하나는 인증, 하나는 폐기한 뒤 Genie One에 물어봅니다.

준비물
  • Genie One을 쓸 수 있는 워크스페이스와 SQL 웨어하우스(서버리스 권장)
  • 실습용 스키마를 만들 수 있는 카탈로그 (아래 <catalog>를 바꿔 넣기)
  • system.certification_status 태그 ASSIGN 권한 (워크스페이스 관리자라면 보통 있음)

1실습 스키마 만들기 1분

SQL
CREATE SCHEMA IF NOT EXISTS <catalog>.genie_ontology_lab
  COMMENT 'Genie Ontology hands-on lab';

2메트릭 뷰 만들고 조회하기 5분

예시 ①의 두 SQL을 차례로 실행합니다. 1995년 세그먼트 다섯 개의 확정 매출이 각각 약 65억 달러로 나오면 성공입니다.

기간을 1995년으로 잡은 이유

samples.tpch의 최근 주문(1998년)은 대부분 배송 완료(F) 상태가 아니어서 확정 매출이 NULL로 나옵니다. 정의가 의도대로 동작한다는 뜻이지만, 처음 보면 오류로 오해하기 쉽습니다.

3'경쟁하는' 구 뷰를 만들고 인증·폐기 표시하기 3분

SQL
-- Legacy view: sums every order status (the definition we want Genie to avoid)
CREATE OR REPLACE VIEW <catalog>.genie_ontology_lab.orders_revenue_old AS
SELECT o_orderdate, SUM(o_totalprice) AS revenue
FROM samples.tpch.orders
GROUP BY ALL;

이어서 예시 ②의 SQL로 orders_metrics는 인증, orders_revenue_old는 폐기 표시합니다. Catalog Explorer에서 두 객체에 체크 표시와 제한 아이콘이 보이면 됩니다.

4Genie One에 물어보기 5분

Genie One에서 이렇게 물어봅니다. 실습 자산이 워크스페이스의 다른 테이블과 섞이지 않도록 스키마를 질문에 넣습니다.

질문
<catalog>.genie_ontology_lab 기준으로 1995년 시장 세그먼트별 매출을 알려줘
실제로 실행해 본 결과 (2026-11-20, Azure Databricks)
  • Genie가 인증된 orders_metrics를 골라 MEASURE(recognized_revenue)로 집계했습니다. 2단계의 SQL 결과와 숫자가 같았습니다.
  • 답변에서 "매출은 인증된 메트릭 뷰 기준이며 배송 완료(F) 주문만 합산"이라고 메트릭 뷰의 정의를 그대로 설명했습니다.
  • orders_revenue_old는 "사용 중단(deprecated)으로 표시돼 있어 쓰지 않았다"고 이유를 밝히고 제외했습니다.
  • Genie의 생각 단계에 온톨로지 검색이 있었지만, 막 만든 자산이라 쓸 만한 스니펫은 아직 없었습니다. 이번 답은 메트릭 뷰의 정의(모델링된 지식)와 인증 표시로 만들어졌습니다.

응답의 인용 아이콘과 그 아래 Genie Ontology를 눌러 어떤 자산과 지식이 쓰였는지 확인해 보세요. 자산을 실제로 쓰다 보면 학습된 스니펫이 생깁니다. 며칠 뒤 같은 질문을 다시 하면 스니펫 인용이 붙는지 볼 수 있습니다.

5Page로 용어 정의 더하기 선택 · UI · 10분

Discover → Pages → Create page에서 도메인을 고르고 "확정 매출" Page를 만듭니다. 동의어("매출", "인식 매출"), 정의("배송 완료 주문 금액의 합계, 진행 중·부분 배송 제외"), 관련 자산(orders_metrics)을 넣고 게시합니다. 그런 다음 스키마 이름 없이 "확정 매출이 뭐야? 1995년 기준으로 보여줘"라고 물어 Page 인용이 붙는지 봅니다.

이 단계는 직접 실행하지 않았습니다

도메인과 Pages는 계정 단위 객체라서 같은 계정의 모든 워크스페이스에 보입니다. 공용 계정에서는 실습용으로 만들지 말고, 정리 계획을 세운 뒤 진행하세요. 위 절차는 공식 문서 기준입니다.

6외부 에이전트로 같은 질문하기 선택 · 5분

예시 ③의 Python 코드로 같은 질문을 보냅니다. 같은 메트릭 뷰를 근거로 한 답이 오는지, 응답의 query_items에 담긴 SQL이 orders_metrics를 쓰는지 확인합니다.

DROP SCHEMA IF EXISTS <catalog>.genie_ontology_lab CASCADE;
